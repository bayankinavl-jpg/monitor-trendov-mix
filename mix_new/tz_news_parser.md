# ТЗ: парсер новостей по ключевым словам

Дата: 11.10.2026

## Цель и контекст

Проект переходит от сверки с сайтами госорганов к поиску регуляторных новостей по ключевым словам в открытых СМИ, потому что госсайты недоступны для автоматического сбора.

Что показали проверки:

- pravo.gov.ru не устанавливает соединение (таймаут), в том числе с компьютера пользователя.
- regulation.gov.ru не ответил на пробный запрос за 15 секунд.
- sozd.duma.gov.ru открывается, но robots.txt запрещает автоматический сбор, а сайт построен как Angular SPA.

Вероятная причина недоступности: часть российских государственных сайтов ограничивает доступ с зарубежных IP-адресов. Облачная среда Claude выходит в сеть не из России; компьютер пользователя тоже получит таймаут, если запрос идет через зарубежный адрес или VPN. Проверка: открыть pravo.gov.ru из российской сети, например из корпоративной сети Точки. Если сайт откроется, сбор по первоисточникам можно вернуть, запустив парсер на машине в российской сети.

**Обновление от 11.10.2026.** Пользователь скачал в браузере RSS-ленты портала publication.pravo.gov.ru (адрес http://publication.pravo.gov.ru/rss). Запрет на обращение к pravo.gov.ru и publication.pravo.gov.ru снят: парсер скачивает ленты портала сам, наравне с лентами СМИ. Запрет на regulation.gov.ru и sozd.duma.gov.ru сохраняется.

**Цель.** По запросу или по расписанию собирать из RSS и сайтов СМИ новости, в которых встречаются заданные ключевые слова о регулировании, и выдавать реестр без дублей: заголовок, ссылка, дата, источник, совпавшие слова, тип изменения, уровень НПА, стадия, тема, коды ОКВЭД, уровень достоверности.

**Пользователь.** Сотрудник, который отслеживает изменения регулирования и разбирает готовую выгрузку вручную.

**Ограничение подхода.** Новость не подтверждает изменение. Запись из выгрузки переносится в реестр регуляторных изменений и в рассылку только после ручной сверки с текстом акта, порядок описан в разделе «Ручная сверка».

## Что меняется

Новости становятся основным источником данных, а автоматическая проверка по первоисточнику заменяется оценкой достоверности и ручной сверкой.

| Аспект | Было | Станет |
| --- | --- | --- |
| Основной источник | Акты на pravo.gov.ru и regulation.gov.ru | Новости СМИ и правовых систем (RSS и рубрики) |
| Статус записи | «Подтверждено» или «не подтверждено» по первоисточнику | Уровень достоверности и статус ручной проверки |
| Проверка | Автоматическая, по первоисточнику | Ручная, очередь по уровню достоверности |
| Привязка к сегментам | Коды ОКВЭД по тексту акта | Коды ОКВЭД по группам «Темы» и «Отрасли» |
| Классификация | Тип изменения | Тип изменения, уровень НПА, стадия документа, тема реестра |
| Ключевые слова | Зашиты в коде (например, «ставк», «перечень») | Вынесены в файл keywords.yml |
| Список источников | Зашит в коде | Вынесен в файл sources.yml |
| Выгрузка | Реестр актов (xlsx, json) | Реестр новостей (xlsx, json, md-отчет) |

**Переиспользуем:** сканер RSS, реестр в SQLite и дедупликацию, выгрузку в xlsx, json и md, классификатор типов изменений, 33 существующих теста, виртуальное окружение и requirements.txt.

**Убираем:** модули sources/pravo_gov.py и sources/regulation_gov.py, заглушку для sozd.duma.gov.ru, проверку статуса по первоисточнику, смоук-тест, который зависит от этих сайтов.

Правила отбора:

1. Слова ищутся в заголовке и аннотации. Поиск идет по основе слова без учета регистра, с заменой ё на е и с учетом словоформ.
2. Новость проходит, если в ней есть слово из группы «Изменения» или «Стадии» и слово из групп «Акты и органы», «Темы» или «Отрасли», и нет слов из «Исключений».
3. Для каждой записи сохраняются совпавшие слова и их группы.
4. Список исключений пополняется по результатам первых запусков, когда станет видно, какой шум попадает в выгрузку.
5. Правка keywords.yml действует со следующего запуска, без изменения кода.
6. Аббревиатуры (НДС, ФНС, ЕГАИС, ЕЭК) ищутся целым словом, без поиска по основе, иначе они совпадут с частью других слов.
7. Региональные и муниципальные акты и судебная практика вне охвата, поэтому они вынесены в «Исключения».

Российская газета и Парламентская газета отличаются от остальных изданий: публикация в них считается официальным опубликованием федеральных законов, а в Российской газете также постановлений Правительства. Записи из этих источников получают высокий уровень достоверности.

Портал publication.pravo.gov.ru — первоисточник: каждая запись ленты — официально опубликованный акт со ссылкой на его текст. Записи портала получают высокий уровень достоверности и стадию «опубликован». Каждая лента портала содержит 200 последних актов; лента министерств и служб покрывает около 10 дней, поэтому запуск нужен не реже раза в неделю. Ленту Конституционного Суда не подключаем: судебная практика вне охвата.

Правила:

1. Приоритет у RSS. Страницы рубрик читаются только там, где нет ленты и где это разрешает robots.txt.
2. Источник, который не ответил или вернул не XML, пропускается. Причина пишется в журнал, запуск продолжается.
3. Список источников лежит в sources.yml. Добавить издание можно без правки кода.
4. Если материал закрыт пейволом, берутся только заголовок, аннотация и ссылка из ленты.
5. Запрещены к обращению: regulation.gov.ru, sozd.duma.gov.ru. Запрет на pravo.gov.ru и publication.pravo.gov.ru снят 11.10.2026.
6. Независимость источников: перепечатка новости агентства (ТАСС, Интерфакс) в другом СМИ считается одним источником с агентством. Если в тексте есть ссылка на агентство, источник записывается по агентству.
7. Источник, недоступный 3 запуска подряд, помечается в листе «Источники» как требующий замены.

## Функциональные требования

Парсер выполняет восемь шагов подряд, каждый можно проверить отдельным тестом.

1. **Сбор.** Прочитать все ленты из sources.yml за период, заданный параметром --days N. По умолчанию 90 для первого запуска, 1 для ежедневного. Для каждой новости получить заголовок, аннотацию, ссылку, дату публикации и название источника.
2. **Нормализация.** Привести ссылки к единому виду (убрать utm-метки и якоря), даты к одному формату и часовому поясу, текст к нижнему регистру с заменой ё на е.
3. **Фильтрация.** Применить правила отбора из раздела «Ключевые слова». У каждой прошедшей новости сохранить совпавшие слова и группы.
4. **Дедупликация.** Отбросить повторы по нормализованной ссылке. Новости с близкими заголовками из разных СМИ объединить в одну запись со списком ссылок и числом независимых источников.
5. **Классификация.** Определить:
    - тип изменения (ставка, перечень, новая обязанность, отмена, новый акт) существующим классификатором;
    - уровень НПА по группе «Акты и органы»: право ЕАЭС, федеральный закон, указ, постановление или распоряжение Правительства, приказ ведомства;
    - стадию документа по группе «Стадии»;
    - тему реестра по группе «Темы»;
    - коды ОКВЭД по таблице соответствия отраслей;
    - номер и дату акта, если они указаны в тексте.

    Если признак не найден, поле остается пустым.
6. **Оценка достоверности.** Присвоить записи уровень:
    - высокий: акт опубликован в Российской газете или Парламентской газете, либо новость Гаранта или КонсультантПлюс с номером и датой акта;
    - средний: номер и дата акта есть в тексте, и новость подтверждена не меньше чем 2 независимыми источниками;
    - низкий: один источник или нет реквизитов акта.
7. **Связь с реестром.** Если номер и дата акта совпадают с актом, который уже есть в реестре регуляторных изменений, запись помечается как относящаяся к этому акту, новая строка в реестре не предлагается.
8. **Накопление.** Записать результат в SQLite-реестр. Запись получает статус «новая», «обновлена» (добавился источник) или «повтор» (уже была в прошлых запусках).

После запуска парсер печатает сводку: сколько источников опрошено и сколько не ответило, сколько новостей прочитано, отобрано и сколько из них новых.

## Результат и формат выгрузки

Каждый запуск создает в папке data/exports/ три файла с датой в имени: news_registry_ГГГГММДД.xlsx, news_registry_ГГГГММДД.json и news_report_ГГГГММДД.md.

В xlsx четыре листа:

1. «Новости»: основной лист.
2. «Источники»: кто ответил, кто нет и почему.
3. «Ключевые слова»: набор, с которым шел запуск.
4. «Сводка по месяцам»: число записей по каждой теме и каждой отрасли по месяцам и число месяцев без записей.

Поля листа «Новости» и json:

| Поле | Содержание |
| --- | --- |
| Дата публикации | Дата и время новости, часовой пояс Москвы |
| Заголовок | Заголовок из ленты |
| Ссылка | Основная ссылка на новость |
| Источники | Число независимых СМИ и все ссылки, если новость продублирована |
| Совпавшие слова | Слова и группы, по которым новость прошла отбор |
| Тип изменения | Ставка, перечень, новая обязанность, отмена, новый акт |
| Уровень НПА | Право ЕАЭС, федеральный закон, указ, постановление или распоряжение Правительства, приказ ведомства |
| Стадия | Проект, внесен, принят в чтении, подписан, опубликован, вступает в силу, утратил силу |
| Тема | Тема реестра по группе «Темы» |
| Отрасль | По группе «Отрасли». Пусто, если не определена |
| Коды ОКВЭД | По таблице соответствия отраслей |
| Реквизиты акта | Номер и дата акта, если указаны в тексте |
| Достоверность | Высокий, средний, низкий |
| Статус записи | Новая, обновлена, повтор |
| Статус ручной проверки | Не проверено, подтверждено, не подтверждено. Заполняется вручную, повторный запуск его не перезаписывает |
| Ссылка на текст акта | Заполняется вручную при сверке |
| Первое обнаружение | Дата первого запуска, на котором новость найдена |

Лист «Сводка по месяцам» нужен для оценки плотности регуляторики по подсегментам при выборе подсегмента для теста рассылки. Число новостей не равно числу актов: один акт дает несколько новостей на разных стадиях. Поэтому для оценки плотности считаются записи с заполненными реквизитами, сгруппированные по акту.

Отчет в формате md содержит сводку запуска: список опрошенных источников с результатом, число новостей по шагам (прочитано, отобрано, новых) и десять самых свежих записей.

Полные тексты статей в выгрузку не попадают: только заголовок, аннотация из ленты и ссылка.

## Ручная сверка

Парсер находит сигнал, подтверждение остается за человеком.

1. Сотрудник берет записи с достоверностью «высокий» и «средний», начиная с самых свежих.
2. По номеру и дате находит текст акта на publication.pravo.gov.ru, в Гаранте, КонсультантПлюс или Российской газете.
3. Заполняет поля «Ссылка на текст акта» и «Статус ручной проверки».
4. Записи со статусом «подтверждено» переносятся в реестр регуляторных изменений.
5. Записи без реквизитов остаются в выгрузке как сигнал и в реестр не переносятся, пока акт не найден.

## Нефункциональные требования

Парсер должен работать на обычном Mac без VPN, не зависеть от сети больше, чем нужно, и соблюдать правила сайтов.

- **Запуск.** Одной командой из активированного окружения: python scripts/run_news.py --days N.
- **Без ИИ-сервисов.** Парсер не обращается к Claude и другим внешним ИИ-сервисам, поэтому VPN для его работы не нужен.
- **Время.** Запуск за 90 дней по всем источникам занимает не больше 10 минут, даже если часть источников недоступна.
- **Сеть.** Таймаут 10 секунд на запрос, один повтор, пауза не меньше 1 секунды между запросами к одному сайту.
- **Этика сбора.** Соблюдать robots.txt, указывать в User-Agent название проекта, не обходить пейволы и ограничения доступа.
- **Настройки в файлах.** Слова в keywords.yml, источники в sources.yml, без правки кода.
- **Журнал.** Для каждого запроса записываются адрес, код ответа и время. Журнал лежит в папке logs/ с датой в имени.
- **Повторяемость.** Повторный запуск за тот же период не создает дублей в реестре и не перезаписывает поля, заполненные вручную.
- **Тесты.** pytest без доступа к сети, на сохраненных образцах лент. Покрыты шаги нормализации, фильтрации, дедупликации, классификации и оценки достоверности.
- **Версии.** Каждое законченное изменение коммитится в git.

## Критерии приемки

Работа принята, когда выполнены все пункты.

- [ ] pytest проходит целиком, включая новые тесты на нормализацию, фильтрацию, дедупликацию, классификацию и оценку достоверности.
- [ ] Запуск с --days 90 завершается за 10 минут или быстрее, даже если часть источников не ответила.
- [ ] Недоступный источник попадает в журнал и в лист «Источники», запуск не падает.
- [ ] В журнале запросов нет обращений к regulation.gov.ru и sozd.duma.gov.ru.
- [ ] В выгрузке нет двух строк с одной ссылкой. Новость из нескольких СМИ дает одну строку со списком ссылок.
- [ ] Повторный запуск за тот же период не добавляет дублей и помечает прежние записи как «повтор».
- [ ] Повторный запуск не перезаписывает поля «Статус ручной проверки» и «Ссылка на текст акта».
- [ ] Добавленное в keywords.yml слово начинает работать со следующего запуска без правки кода.
- [ ] Новость со словом из «Исключений» не попадает в выгрузку, это покрыто тестом.
- [ ] Запись с номером и датой акта получает уровень НПА, стадию и уровень достоверности.
- [ ] Лист «Сводка по месяцам» строится, и сумма по нему совпадает с числом записей на листе «Новости».
- [ ] Контрольный список из 10 изменений, опубликованных за последние 90 дней, составлен до запуска. Парсер находит не меньше 8 из них.
- [ ] Ручная проверка 20 случайных строк: не меньше 16 (80%) по делу. Порог согласовать в разделе «Открытые вопросы».
- [ ] Изменения закоммичены в git, README.md описывает установку, запуск и настройку двух файлов.
