# Реестр регуляторных новостей (опт и производство)

Ищет в открытых СМИ новости о регуляторных изменениях, затрагивающих
опт и производство, по ключевым словам, и собирает реестр новостей
(xlsx/json/md-отчёт) для последующей ручной сверки сотрудником и переноса
подтверждённых изменений в реестр регуляторных изменений.

Новость сама по себе не подтверждает изменение — парсер находит сигнал,
подтверждение по тексту акта остаётся за человеком (см. раздел «Ручная
сверка» в `tz_news_parser.md`).

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt   # requirements.txt — без pytest, для прод-окружения
```

## Запуск

Одной командой из активированного окружения:
```bash
python scripts/run_news.py --days N
```
По умолчанию: 90 дней при первом запуске (пустой реестр), 1 день при
последующих (ежедневный режим).

Каждый запуск создаёт в `data/exports/` три файла с датой в имени:
`news_registry_ГГГГММДД.xlsx` (листы «Новости», «Источники», «Ключевые
слова», «Сводка по месяцам»), `news_registry_ГГГГММДД.json` (полный
дамп всех полей) и `news_report_ГГГГММДД.md` (сводка запуска). Журнал
отдельных HTTP-запросов (адрес, код ответа, время) пишется в
`logs/requests_ГГГГММДД.log`.

Повторная выгрузка без повторного сбора:
```bash
python cli.py export --format both --out data/exports/
```

Тесты (без сети, на сохранённых фикстурах):
```bash
pytest tests/
```

## Настройка без правки кода

- **`keywords.yml`** — шесть групп ключевых слов (акты и органы, стадии,
  изменения, темы, отрасли с кодами ОКВЭД, исключения) + список
  аббревиатур, которые ищутся целым словом. Правка действует со
  следующего запуска.
- **`sources.yml`** — список RSS-источников (`name`, `focus`, `feed_url`,
  `trust_tier`). `trust_tier: official_publication` (Российская
  газета/Документы, Парламентская газета) и `legal` (Гарант,
  КонсультантПлюс) повышают уровень достоверности записи. Часть адресов
  лент отмечена в комментариях как «уточнить» — на первом запуске они
  либо подтвердятся, либо источник попадёт в журнал как недоступный
  (без паники — запуск продолжается).

## Источники, к которым парсер никогда не обращается

`pravo.gov.ru`, `publication.pravo.gov.ru`, `regulation.gov.ru`,
`sozd.duma.gov.ru` — недоступны для автоматического сбора (таймауты,
запрет `robots.txt`, Angular SPA — см. `tz_news_parser.md`). Список
зафиксирован в `config.FORBIDDEN_DOMAINS`; `sources/sources_config.py`
отказывается загружать `sources.yml`, если туда случайно попадёт один
из этих доменов.

## Как это работает (8 шагов)

Сбор (`sources/news_scan.py`) → нормализация ссылок/дат/текста
(`pipeline/normalize.py`) → фильтрация по ключевым словам
(`pipeline/keywords_engine.py`) → дедупликация и кластеризация по
источникам (`pipeline/dedupe_news.py`) → классификация — тип изменения,
уровень НПА, стадия, тема, отрасль/ОКВЭД, реквизиты акта
(`pipeline/classify_news.py`) → оценка достоверности
(`pipeline/credibility.py`) → связь с реестром актов по номеру/дате
(`pipeline/link_registry.py`) → накопление в SQLite с сохранением полей
ручной проверки между запусками (`registry/db.py: upsert_news_item`).
Всё оркестрирует `pipeline/runner_news.py`.

## Ручная сверка

1. Сотрудник берёт записи с достоверностью «высокий» и «средний» в
   `data/exports/news_registry_*.xlsx`, начиная с самых свежих.
2. Находит текст акта по номеру и дате в Гаранте, КонсультантПлюс или
   Российской газете.
3. Заполняет вручную колонки «Ссылка на текст акта» и «Статус ручной
   проверки» — повторный запуск парсера эти поля не перезаписывает.
4. Записи со статусом «подтверждено» переносятся в реестр регуляторных
   изменений.

## Ограничения, которые нужно знать

- Фильтр ключевых слов (`keywords.yml`) и привязка отрасль→ОКВЭД — это
  эвристика по словам из ТЗ, не точный классификатор; список исключений
  пополняется по мере появления шума в выгрузке.
- Дедупликация близких заголовков из разных СМИ — fuzzy-сравнение
  строк (`difflib`), порог подобран приблизительно; схожие по смыслу, но
  по-разному сформулированные заголовки иногда остаются раздельными
  записями.
- Часть адресов RSS-лент в `sources.yml` — лучшее предположение на
  момент написания; при недоступности источник просто помечается в
  журнале, запуск не падает.
- Формальная приёмка (контрольный список из 10 известных изменений,
  ручная проверка 20 случайных строк, порог 80% — см. `tz_news_parser.md`)
  сознательно отложена; парсер сейчас проверен только на том, что
  работает end-to-end без сети и на живом прогоне без ошибок.
