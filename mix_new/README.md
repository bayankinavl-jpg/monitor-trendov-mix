# Монитор трендов Микс: регуляторика и рыночные тренды (опт, производство, IT, услуги)

Читает RSS-ленты СМИ, правовых систем, портала pravo.gov.ru и публичные
Telegram-каналы. Делает две вещи:

- **Регуляторика.** Отбирает новости и новые акты о регуляторных
  изменениях, оценивает достоверность каждой записи и собирает реестр
  (xlsx, json, md-отчёт).
- **Тренды.** Считает, какую долю всех прочитанных статей занимают
  бизнесовые и рыночные темы и упоминания конкурентов, и сравнивает с
  предыдущим периодом (растёт, новая, устойчивая, снижается).

Результат — страница монитора `data/exports/report_artifact.html` с
вкладками «Регуляторика» и «Тренды» и справочным режимом «Источники и
словари». Claude или другие внешние сервисы для работы не нужны.

Ручной проверки нет: достоверность оценивает программа по признакам и
сохраняет основания оценки. Программа не читает текст акта, поэтому оценка
показывает доверие к записи, а не подтверждает изменение.

## Установка

Нужно:
- macOS или Linux (скрипты `run.sh`, `monitor.sh` написаны для bash; на
  Windows — через WSL);
- Python 3.11 или новее (`python3 --version`);
- интернет из российской сети: часть госсайтов не отвечает зарубежным
  адресам и VPN.

```bash
git clone <адрес репозитория>
cd <папка репозитория>/mix_new
python3 -m venv .venv                 # изолированное окружение Python
source .venv/bin/activate             # включить окружение
pip install -r requirements-dev.txt   # библиотеки; requirements.txt — без pytest
pytest tests/                         # проверка: все тесты должны пройти
./run.sh                              # первый сбор (за 90 дней)
```

База `data/registry.sqlite3`, выгрузки и журналы в репозиторий не
попадают: у каждого они свои и создаются при первом запуске. История для
трендов копится с первого запуска, статусы появляются через 1–2 недели
ежедневных запусков.

## Ежедневный автозапуск (macOS)

```bash
scripts/autorun.sh install   # включить запуск каждый день в 9:00
scripts/autorun.sh status    # включён ли и чем закончился последний запуск
scripts/autorun.sh now       # запустить сейчас
scripts/autorun.sh remove    # выключить
```
Скрипт сам подставляет путь к папке проекта в задачу планировщика
`launchd`. Журнал — `logs/autorun.log`. Mac должен быть включён в 9:00;
пропущенные дни следующий запуск подберёт сам.

## Запуск

Одной командой из папки проекта:
```bash
./run.sh
```
`run.sh` сам переходит в папку проекта, активирует виртуальное окружение
`.venv` и запускает `scripts/run_news.py`. Окружение активировать вручную
не нужно.

Период сбора задаётся параметром `--days`:
```bash
./run.sh --days 7
```
Без `--days`: 90 дней при первом запуске (пустой реестр), 1 день при
следующих.

Та же команда без `run.sh`:
```bash
source .venv/bin/activate && python scripts/run_news.py
```

Ленты Гаранта и КонсультантПлюс отдают только последние 10 и 50
документов, поэтому для полного охвата запускайте программу каждый день.

Каждый запуск создаёт в `data/exports/` три файла с датой в имени:
`news_registry_ГГГГММДД.xlsx` (листы «Новости», «Источники», «Ключевые
слова», «Сводка по месяцам»), `news_registry_ГГГГММДД.json` (все поля) и
`news_report_ГГГГММДД.md` (сводка запуска). Журнал HTTP-запросов (адрес,
код ответа, время) пишется в `logs/requests_ГГГГММДД.log`.

Запуск с лендинга монитора:
```bash
./monitor.sh
```
Открывает в браузере `http://127.0.0.1:8765` — страницу монитора
`data/exports/report_artifact.html` с панелью «Запуск парсера» (поле
«за сколько дней» и кнопка). Страница собирается из реестра скриптом
`scripts/build_landing.py`: после каждого запуска парсера и при каждом
открытии пульта. Вкладки: «Регуляторика» (фильтры по сфере, нише,
периоду и достоверности, поиск) и «Тренды» (темы и конкуренты). Кнопка
«Источники и словари» открывает справку: кто ответил в последнем запуске,
ниши и слова регуляторики, темы и конкуренты. После успешного запуска кнопкой страница обновляется
сама. Сервер доступен только с этого компьютера; остановить — Ctrl+C.

Только пересобрать страницу без нового сбора: `python scripts/build_landing.py`.

Повторная выгрузка без нового сбора:
```bash
python cli.py export --format both --out data/exports/
```

Тесты (без сети):
```bash
pytest tests/
```

## Настройка без правки кода

- **Ниши.** В `keywords.yml`, раздел `industries`, у каждой ниши есть `sphere`
  (Опт и производство — по умолчанию, IT, Услуги) и коды ОКВЭД.
  IT = ОКВЭД 63. Новая ниша — новый блок `label / sphere / words / okved`.
  Уже сохранённые записи получают нишу при повторном нахождении в ленте.
- **`keywords.yml`** — группы ключевых слов (акты и органы, стадии,
  изменения, темы, исключения), отрасли с названием и кодами ОКВЭД,
  аббревиатуры. Слова сравниваются по нормальной форме, поэтому писать их
  можно в любой форме: «ставка» найдёт «ставки», «ставку». Аббревиатуры
  ищутся целым словом.
- **`sources.yml`** — RSS-источники (`name`, `focus`, `feed_url`,
  `trust_tier`). `official_publication` (Российская газета, Парламентская
  газета) и `legal` (Гарант, КонсультантПлюс) повышают оценку
  достоверности.

## Тренды

Вкладка «Тренды» на странице монитора:

- **Темы и Конкуренты.** Словарь — `trends.yml`: темы (о чём пишут, с типом
  по STEEPLE) и конкуренты (кто упоминается). Темы ищутся по нормальной
  форме слов, конкуренты — по названию с русскими окончаниями. Статьи об
  одном событии из разных изданий склеиваются в **сюжет**, и тренд
  считается по сюжетам, а не по перепечаткам. Тренд — доля сюжетов темы
  среди всех прочитанных статей за период в сравнении с таким же
  предыдущим периодом (растёт, новая, устойчивая, снижается). У каждой
  темы видно, кто о ней пишет: деловые и отраслевые СМИ, исследования,
  стартапы, Telegram (поле `category` в `sources.yml`).
Правка `trends.yml` действует при следующей сборке страницы: сохранённые
статьи размечаются заново. Ленты актов (pravo.gov.ru, Гарант,
КонсультантПлюс) в тренды не берутся. Все прочитанные статьи хранятся в
таблице `articles`, карточки — в `trend_cards` и `trend_card_signals`.

Telegram-каналы подключаются в `sources.yml` с `kind: telegram` и адресом
`https://t.me/s/<канал>`. Читается публичная веб-версия канала (около 20
последних постов), поэтому запускать сбор нужно ежедневно.

## Карточки трендов (отключены)

Раздел в работе и на странице не показывается. Заготовка — модуль
`pipeline/trend_cards.py`: раз в неделю Claude API формулирует 3–6 трендов
(направлений изменений) по сюжетам месяца. Модуль не вызывается при
запуске, чтобы включить — подключить его в `scripts/run_news.py` и вернуть
раздел на страницу.

## Авто-оценка достоверности

| Оценка | Когда ставится |
|---|---|
| Высокая | официальное издание и (номер и дата акта или стадия «опубликован»/«подписан»); либо правовая система и номер и дата акта |
| Средняя | номер и дата и не меньше 2 независимых СМИ; либо упомянут известный закон и не меньше 2 независимых СМИ; либо официальное издание или правовая система без реквизитов |
| Низкая | остальное |

Основания оценки сохраняются у каждой записи (колонка «Основание оценки»
в xlsx).

## Справочник законов

`reference/law_aliases.json` — 1055 актов РФ с вариантами написания, взят
из проекта LawRegexParser (см. `reference/SOURCE.md`). По нему программа
находит в новости упомянутые законы: по номеру («381-ФЗ»), названию в
кавычках, названию кодекса («Налоговый кодекс», «НК РФ»). В справочнике
акты до 2025 года включительно.

## Портал официального опубликования

Программа скачивает RSS-ленты `publication.pravo.gov.ru` сама
(`trust_tier: primary_source` в `sources.yml`). Адрес ленты:
`http://publication.pravo.gov.ru/api/rss?block=<раздел>&pageSize=200`, разделы:
`government`, `president`, `federal_authorities`, `council_1` (Совет
Федерации), `council_2` (Государственная Дума). Значение `pageSize`
меньше 10 портал не принимает. Адрес `/rss` — это
HTML-страница со списком лент, а не лента. Если источник вернул не RSS,
он пропускается, причина пишется в журнал. Запись ленты — сам акт со
ссылкой на текст, поэтому она получает высокую достоверность и стадию
«опубликован». Уровень акта определяется по началу заголовка («Указ
Президента», «Постановление Государственной Думы» и т. д.). Каждая лента
содержит 200 последних актов; лента министерств и служб покрывает около
10 дней, поэтому запускайте программу не реже раза в неделю. Записи с
разными номерами актов не объединяются, даже если заголовки похожи.

## Источники, к которым программа не обращается

`regulation.gov.ru` и `sozd.duma.gov.ru` — недоступны для
автоматического сбора (таймаут, запрет `robots.txt`, Angular SPA — см.
`tz_news_parser.md`). Список зафиксирован в `config.FORBIDDEN_DOMAINS`;
если один из этих доменов попадёт в `sources.yml`, программа откажется
запускаться. Запрет на `pravo.gov.ru` снят 11.10.2026.

## Как это работает (8 шагов)

Сбор (`sources/news_scan.py`) → нормализация ссылок, дат, текста
(`pipeline/normalize.py`) → отбор по ключевым словам в нормальной форме
(`pipeline/keywords_engine.py`, `pipeline/morph.py`) → объединение повторов
из разных СМИ (`pipeline/dedupe_news.py`) → классификация: тип изменения,
уровень, стадия, тема, отрасль и ОКВЭД, реквизиты, упомянутые законы
(`pipeline/classify_news.py`, `pipeline/act_reference.py`) → авто-оценка
достоверности (`pipeline/credibility.py`) → связь с реестром актов по
номеру и дате (`pipeline/link_registry.py`) → запись в SQLite
(`registry/db.py`). Всё оркестрирует `pipeline/runner_news.py`.

## Ограничения

- Правило отбора из ТЗ не проверяет тему опта и производства. Ленты
  правовых систем публикуют все федеральные акты, и в реестр попадают акты
  не по теме (например, регламенты МВД). Высокая достоверность не
  означает, что акт касается опта и производства.
- Отрасль и ОКВЭД определяются по стартовому списку слов в
  `keywords.yml`, это не полный справочник.
- Объединение повторов сравнивает заголовки (`difflib`). По-разному
  сформулированные заголовки одной новости могут остаться двумя записями.
- Таблица актов для шага «связь с реестром» пустая, поэтому связь пока не
  срабатывает.
- Поля ручной проверки (`manual_check_status`, `act_text_url`) оставлены в
  базе, но не используются; правки в xlsx в базу не попадают.
- Контрольный список известных изменений для проверки полноты не
  составлен.
